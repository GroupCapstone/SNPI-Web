## System Architecture

The SNPI platform operates on a decoupled **Headless REST API Architecture**:

- **Backend Engine (`snp-sms-api`)**: Express 5, TypeScript, MongoDB Replica Set (`rs0`), 7-layer modular monolith API.
- **Frontend Portal (`snp-sms-web`)**: Next.js 16 (App Router), React 19, Tailwind CSS.
- **Documentation Portal (`snp-sms-docs`)**: Nextra static documentation engine powered by MDX.

## 5 Bounded Contexts

All system endpoints are organized into 5 cohesive business domains:

1. **Identity & Access**: Authentication, user accounts, core roles, RBAC permissions, and campus branches.
2. **Academic Operations**: Academic years, study terms, programs, departments, classes, subjects, and schedules.
3. **Student Lifecycle**: Student profiles, admissions, enrollments, daily attendance, and campus transfers.
4. **Assessment & Grading**: Examination sessions, continuous evaluations, subject scores, and term report cards.
5. **Finance & Accounting**: Tuition structures, payment plans, fee collections, transactions, and financial auditing.
